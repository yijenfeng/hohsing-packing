# 合欣包裝進度

合欣電業 OHM／YAZAWA 六張訂單（1475608061–63、00017614–16）的包裝與車台進度網站。

- **網頁**：放在 GitHub Pages（`index.html`、`plan.json`、`config.js`）。
- **資料**：記錄進度、改派、順序、料齊勾選都存在 Google 試算表 [合欣包裝進度_資料](https://docs.google.com/spreadsheets/d/1_1VpYl_TeBOKCt83zs_lhXaYj6iR1MbI4RM6hwzy5u4/edit)，由 `apps-script/Code.gs` 提供讀寫。
- **權限**：不設密碼，知道網址的人都能看、也能新增和更正記錄。記錄者名字由使用者自己填。

## 網站功能

| 分頁 | 內容 |
|---|---|
| 各單狀況 | 每張單的預計包完、緩衝工作天、已包百分比、各品號進度、人力負荷 |
| 進度比較 | 實際進度和排程比，超前或落後幾人天（人員／訂單／品號／車台） |
| 記錄進度 | 輸入每天包裝與車台數量；累計與完成百分比；更正、作廢、復原；下載 CSV 備份 |
| 每日工作 | 每人每天預計包哪個品號、幾小時、多少個 |
| 排程 | 依實際進度重新推算；可改派、置頂、上下移動順序 |
| 料齊 | 各品號料齊期限與到料勾選 |

## 記錄資料的保護

- 程式**沒有刪除記錄的功能**：網頁沒有刪除按鈕，後端 `Code.gs` 也拒絕刪除「記錄進度」。
- 「作廢」只是不計入排程，可以復原；「更正」會在 `history` 欄保留修改前的數值。
- 每一次寫入都另外記在試算表的「異動紀錄」工作表。
- 更新網站程式（`index.html`、`plan.json`）不會動到試算表裡的資料。

## 設定資料來源（第一次，約 5 分鐘）

1. 打開試算表 **合欣包裝進度_資料**（在 Google Drive 的 OHM PO 資料夾）。
2. 上方選單「擴充功能 → Apps Script」。
3. 把編輯器裡原本的程式全部刪掉，貼上本 repo 的 `apps-script/Code.gs`，按儲存。
4. 回到編輯器，上方函式選 `setup`，按「執行」。第一次會要求授權：選你的帳號 →「進階」→「前往（不安全）」→「允許」。執行完試算表會出現「記錄進度、改派、順序、料齊」工作表。
5. 右上「部署 → 新增部署作業」→ 齒輪選「網頁應用程式」：
   - 執行身分：**我**
   - 具有存取權的使用者：**所有人**
   - 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。
6. 在 GitHub 打開 `config.js`，把網址貼進 `apiUrl: ''` 的引號裡，提交。

之後如果修改了 `Code.gs`，要到「部署 → 管理部署作業 → 編輯 → 版本：新版本 → 部署」，網址不變。

## 開啟 GitHub Pages

repo 的 Settings → Pages → Source 選「Deploy from a branch」，Branch 選 `main`、資料夾 `/ (root)`，儲存。約一分鐘後網站會出現在 `https://<帳號>.github.io/<repo 名稱>/`。

- `plan.json`：排程基準（每段工作的人員、品號、數量、人天、開始與結束時間、車台批次、國定假日、幫手上工期間）。

- 工時：吊入 1,300、袋入 3,400、卡入 5,100 PCS/人天，裝箱 17 箱/人天；車台 FG1E 14,000 顆/天；每天 08:00–12:00、13:00–17:00，週末與國定假日不排，換工作 15 分鐘。
- `tools/`：產生 `plan.json` 的腳本（`extract_plan.py` 從排程 xlsx 匯出；`regen_1475608061.js` 加入上述三個品號並重排；`run_test.js` 用來在 Node 中跑網頁的排程邏輯）。
